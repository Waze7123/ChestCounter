1. Resumo para o dono do negócio

O site está acessível e usa ligação segura, mas encontrámos uma falha crítica no formulário de contacto que pode permitir a alguém ler dados da base de dados da loja — incluindo nomes e emails de clientes. Recomendamos corrigi-la esta semana. As restantes três falhas são de gravidade média ou baixa e corrigem-se em menos de uma hora.

2. Falhas encontradas

F-01

Formulário de contacto vulnerável a injeção SQL

Crítica
O que é
O campo "email" do formulário é enviado diretamente para a base de dados, sem proteção. Um atacante pode escrever comandos em vez de um email.
Impacto no negócio
Acesso aos dados dos clientes (nomes, emails, encomendas). Pode obrigar a notificar a CNPD em 72 horas e levar a coimas do RGPD.
Como confirmámos
Teste controlado, sem alterar nem extrair dados reais, dentro da janela autorizada.
Como corrigir
Usar consultas parametrizadas no ficheiro contacto.php, linha 48: 
// Antes (vulnerável)
$q = "SELECT * FROM leads WHERE email = '$email'";

// Depois (seguro)
$stmt = $pdo->prepare("SELECT * FROM leads WHERE email = ?");
$stmt->execute([$email]);
F-02

Cabeçalhos de segurança em falta (HSTS e CSP)

Média
O que é
O servidor não envia as instruções que dizem ao navegador para usar sempre HTTPS e para bloquear código de origem desconhecida.
Como corrigir
No painel do alojamento ou no ficheiro .htaccess: 
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
Header always set Content-Security-Policy "default-src 'self'; img-src 'self' data:"
F-03

Certificado aceita protocolos antigos (TLS 1.0 e 1.1)

Média
O que é
O site ainda aceita versões de encriptação antigas, com fraquezas conhecidas.
Como corrigir
Pedir ao alojamento para ativar apenas TLS 1.2 e 1.3. Na maioria dos painéis é uma opção de um clique.
F-04

Versão do WordPress visível no código da página

Baixa
O que é
A página indica a versão exata do WordPress, o que ajuda um atacante a procurar falhas conhecidas dessa versão.
Como corrigir
Atualizar o WordPress e remover a etiqueta "generator" (por exemplo, com um plugin de segurança).

3. Plano de ação recomendado

  1. Esta semana: corrigir F-01 (falha crítica).
  2. Este mês: corrigir F-02 e F-03 com o alojamento.
  3. Quando possível: F-04 e manter o WordPress sempre atualizado.
  4. Depois das correções: pedir o novo teste incluído para confirmar que ficou tudo resolvido.

4. O que foi testado

Ligação segura e certificado · cabeçalhos de segurança · ficheiros expostos · injeção (SQL e XSS) · autenticação e sessões · controlo de acessos · versões de software. Não foram feitos testes de negação de serviço nem qualquer ação destrutiva.
